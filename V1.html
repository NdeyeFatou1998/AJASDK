Implémentation V1

AJASDK — spécification d’implémentation

Bibliothèque PHP mince. Elle n’accède pas à la base du site, n’expose aucun webhook, n’implémente aucun statut métier. Elle envoie et reçoit du JSON vers AJABACKEND. Le plugin Woo (AJACONNECTOR) doit dépendre de ce client pour ne pas dupliquer HTTP.

Sens de l’intégration. Un site déjà déployé n’ouvre pas son API à AJA. Le développeur du site appelle AJA (ce SDK) depuis son checkout et depuis un cron. Node/Python : pas de SDK V1, ils recopient les 4 routes (voir AJABACKEND).

1. Rôle fonctionnel

  • orders.create / orders.update — pousser une commande ou une MAJ née sur le site.
  • commands.pending — lire la file.
  • commands.ack — confirmer ou refuser une action.
  • Retries idempotents sur 429 / 5xx, timeout, JSON error mapping.

3. Surface publique

use Aja\Client;
use Aja\Dto\OrderInput;

$aja = new Client(
    apiKey: getenv('AJA_KEY'),
    baseUrl: getenv('AJA_URL') ?: 'https://api.aja.app'
);

$aja->orders()->create(new OrderInput(
    externalId: (string) $commande->id,
    status: 'new',
    allowedNext: ['confirmed', 'cancelled'],
    paymentStatus: 'pending',
    paymentMode: 'cod',
    total: 15000,               // entier
    currency: 'XOF',
    customer: [
        'name'  => $commande->client_nom,
        'phone' => $commande->client_tel,
        'email' => $commande->client_email,
    ],
    lines: [
        ['name' => 'Pagne', 'quantity' => 1, 'unit_price' => 15000, 'extras' => []],
    ],
    extras: ['quartier' => 'Plateau'],
));

$aja->orders()->update('882', [
    'status' => 'confirmed',
    'allowed_next' => ['preparing', 'cancelled'],
    'payment_status' => 'paid',
]);

foreach ($aja->commands()->pending() as $cmd) {
    if ($cmd->type !== 'order.transition') {
        continue;
    }
    try {
        $monSite->changerStatut($cmd->externalId, $cmd->payload['status']);
        $aja->commands()->ack($cmd->id, ok: true, status: $cmd->payload['status'], allowedNext: $monSite->prochainsStatuts($cmd->externalId));
    } catch (DomainReject $e) {
        $aja->commands()->ack($cmd->id, ok: false, reason: $e->getMessage());
    }
}

4. Ce que le développeur d’un site déjà en prod écrit

  1. Composer (ou copie du dossier src/ si pas de Composer) + env AJA_KEY.
  2. Un appel après l’INSERT commande existant — ne pas remplacer leur modèle.
  3. Un cron (crontab */1 * * * * ou équivalent) vers un script bin/aja-poll.php d’exemple fourni, qu’ils branchent sur leur changerStatut.
  4. Quand leur admin change un statut : orders()->update.

Fichiers d’exemple à livrer :

examples/
  checkout-hook.php     # 15 lignes à coller
  cron-poll.php         # boucle pending + TODO métier
  status-from-admin.php

La doc narrative pour humains est aussi sur AJAWEB. Le SDK reste la source des signatures.

5. Poll — règles

  • Timeout HTTP 10 s. Retry 3 fois, backoff 200 ms × 2, seulement GET pending et POST orders (idempotent). Ack : retry si réseau, pas si 409 (déjà acked).
  • Ne pas ACK avant le succès métier local. Si le cron crash après update local et avant ack, le prochain poll représentera la même command : leur changerStatut doit être idempotent (même statut = no-op).
  • User-Agent : aja-php-sdk/1.0.

6. Mapping d’erreurs

HTTPException
401ApiException INVALID_KEY — clé à corriger, ne pas retry en boucle
400 VALIDATIONApiException, message backend
404PATCH d’une commande inconnue
429 / 5xxretry puis Network/ApiException

Le checkout du site ne doit pas échouer si AJA est down : catch, log, optionnellement table locale aja_outbox (hors SDK ; mentionnée en exemple). V1 SDK : throw, l’intégrateur décide. L’exemple checkout-hook capture et log pour ne pas casser la vente.

8. Hors V1

  • SDK Node, Python, Go.
  • Handlers inbound onProductCreate (spec initiale) — remplacés par le poll.
  • verifyWebhook HMAC — pas de webhook inbound.
  • Upload d’images, products CRUD.

Quand un type d’action V2 apparaît, ajouter une constante CommandType::PRODUCT_UPSERT sans casser pending() (liste générique).

9. Critère de fin

  • Les tests mockés passent pour create, upsert, pending, ack ok/ko.
  • L’exemple cron, branché sur un script PHP local fake, consomme une command créée via l’API app.
  • Le plugin Woo compile/tourne en instanciant Aja\Client — pas un second client HTTP.
  • Un site custom sans Composer peut copier src/ et un autoload.php PSR-4 de 10 lignes fourni.
