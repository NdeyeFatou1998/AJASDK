AJASDK — conventions

PHP 8.1+, declare(strict_types=1);, PSR-4 namespace Aja\, PSR-12, ext-curl only. The SDK never touches the merchant database.

Fichiers

ClassPath
Aja\Clientsrc/Client.php

One class per file, filename = class name. Examples stay under examples/ and are commented as copy-paste templates, still in English comments with French string literals only if they echo to the shop admin.

Commentaires (English)

<?php
declare(strict_types=1);

namespace Aja\Api;

/**
 * Site-facing orders: create (upsert) and patch by the shop's external_id.
 */
final class OrdersApi
{
    /**
     * POST /v1/orders. Safe to retry: the backend upserts on external_id.
     *
     * @throws ApiException|NetworkException
     */
    public function create(OrderInput $input): void
    {
    }
}

Do not log the API key. Map HTTP bodies through ErrorCode (ERRORS.html). Integrators switch on getErrorCode(). Do not echo getMessage() to shoppers. COMMAND_ALREADY_ACKED is success.

Comportement

  • Pas de Guzzle. Interface HttpClient pour les tests.
  • User-Agent aja-php-sdk/1.0.0.
  • Ignore unknown command type in examples; never ACK a type we do not understand unless V1 connector policy says reject (plugin Woo documents that separately).
  • BC : no breaking public method without a major Composer version. New methods OK.
